## Limits of these checks
JSON/schema rejection checks validate optional exchange-record structure and certain inconsistent flags, not truth of source claims, AI reasoning or an installed controller. A structurally valid record is not proof that a service exists. The 32 new expected-behavior cases and the preserved 32 sample/context plus 16 controller cases were not newly run against an AI model or a company tenant. User-supplied prior Copilot outputs informed the revisions; their retrieval/execution was not independently reproduced by the package creator.

No corporate mailbox, real attachment, PLM record, scheduled worker, live write/send, universal client compatibility or quantitative time saving was tested in this build. Runtime availability and relevant tenant acceptance checks remain required. The optional implementation files do not install those services.
