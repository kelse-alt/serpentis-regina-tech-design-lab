# Implementation handoff - version 3.0

The beginner route is on-demand reading and drafts displayed in chat. Do not require a retrieval worker, database, approval controller or folder enumeration merely to use that route. A named custom agent requires its actual email knowledge/tool capabilities; knowledge text does not grant them.

This is a configuration and prompt package, not a managed solution, add-in, installed connector or importable skill ZIP. No company tenant installation, scheduled flow or live send was performed while preparing it. The earlier private fictional-data demo is not required and is not an implementation of the v3 native route.

When fuller automation is requested, agree a concrete scope and provision only the missing capabilities. Default to read/review; do not mass-send historic backlog items. The optional source contracts are logical contracts, not existing Microsoft operation names.

End-user route:
- Route A: supported native Copilot in Outlook; start with a bounded, labeled preview.
- Route B: a configured custom agent with actual email knowledge or an approved read tool; recheck license/tenant availability.
- Supplied-content fallback: use only content provided within approved scope, label no live retrieval.
- Full audit / scheduled action service: separately built and tested, not a prompt-only feature.

Do not copy a maker's mailbox/profile into another user's onboarding. Each user needs the correct account connection, isolated context and current role/approval boundaries. Treat direct group preparation differently from passive circulation or ambiguous shared decisions.

The optional reference and historical tests retain earlier terminology and stage/controller examples. They are not the current user setup instructions. Current instructions and explicit company policy take precedence. Advanced all-history gates are not blockers for a limited read-only preview.
