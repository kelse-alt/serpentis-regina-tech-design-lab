# Optional checks for a team pilot
Beginners do not need these files to start. Use fictional data before real actions.

Run the 32 v3 scenarios against the intended model/runtime and record actual responses, source evidence, pass/fail, reviewer, version and date. These scenarios are acceptance expectations, not executed model tests. The preserved 32 legacy sample/context and 16 v2 full-service/controller scenarios remain advanced reference tests with their original scope.

Minimum live pilot: verify account and actual multi-thread retrieval; distinguish matches from reviewed content; check sent history; recognize a clear group preparation instruction; retain a completed task outside priorities; suppress a duplicate or early chase; route technical decisions; test new-starter onboarding and an unavailable attachment. Do not create live sends just to populate a test.

The reported user pilot informed these corrections but did not independently verify all mailbox history, long-term memory, a configured flow or a live record change. Local package/schema/format checks do not prove agent behavior or company readiness. The current validation report states exactly what was checked.

Track net admin time before/after, factual corrections, missed/false tasks, accepted drafts, duplicate/unauthorized actions and useful ownership clarification. Establish numeric targets with the actual team; no time-saving percentage is promised.
